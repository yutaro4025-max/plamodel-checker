A
PART A — Excel ルーティングテーブルの構築
フォルダと承認者の対応をExcelで管理する。フロー本体を触らずに宛先を追加・変更できる仕組み。
A1
Excel — ファイル作成と配置
SharePoint 上に Excel ファイルを新規作成する
  1. SharePoint の対象サイトを開く
  2. 業務ファイルが保存されているライブラリとは別のライブラリに移動する
    （例: 「管理ツール」「自動化設定」など専用ライブラリを作成するか、既存の別ライブラリを使用）
  3. 「＋ 新規」→「Excel ブック」をクリック
  4. ファイル名を 承認ルーティング に変更して保存する
配置場所が重要: 業務ファイルのライブラリ（荷姿設定書があるライブラリ）に置くと、このExcelファイルを更新するたびにフローが誤起動する。必ず別ライブラリに配置すること。
A2
Excel — テーブル作成
テーブル「T_ルーティング」を作成する

まずセル A1 から右に向かって列ヘッダーを入力する。

A1: 製作所　　B1: 領域　　C1: 部門　　D1: 工程　　E1: パスキー　　F1: 宛先メール　　G1: 宛先名
列列名種類内容・用途
A製作所 手入力 SharePoint の最上位フォルダ名（実際のフォルダ名と完全一致させる）
B領域 手入力 2階層目のフォルダ名（領域1〜5）
C部門 手入力 3階層目のフォルダ名（部門1〜8）
D工程 手入力 4階層目のフォルダ名（工程1〜8）。この単位で承認者が決まる。
Eパスキー 数式・自動 A〜D列を「/」でつないだ文字列。Power Automate がパス照合に使うキー。手入力不要。
F宛先メール 手入力 この工程の承認者の Microsoft 365 メールアドレス
G宛先名 手入力 承認者の表示名（フロー内では使わない。管理・確認用）

ヘッダー入力後、以下の手順でテーブル形式に変換する。

  1. セル A1 をクリックして選択する
  2. Excel の上部メニュー「挿入」→「テーブル」をクリック
  3. ダイアログで範囲 $A$1:$G$1 になっていることを確認する（後でデータを追加すると自動的に拡張される）
  4. 「先頭行をテーブルの見出しとして使用する」にチェックが入っていることを確認して「OK」
  5. テーブルが作成されたら、テーブル内のどこかをクリックして選択状態にする
  6. 上部に表示される「テーブルデザイン」タブをクリック
  7. 左端の「テーブル名」欄を T_ルーティング に書き換えて Enter を押す
確認ポイント: テーブル名を変更したら、Excelを一度保存する。テーブル名が正しく設定されているとPower Automateのドロップダウンに「T_ルーティング」と表示される。
A3
Excel — 数式設定
パスキー列（E列）に自動生成の数式を設定する

パスキーは「製作所/領域/部門/工程」の形式で、Power Automate がファイルの保存パスと照合するためのキー文字列。テーブル形式にしておくと、新しい行を追加するたびに数式が自動コピーされる。

  1. A列〜D列に1行分のデータを入力する（数式確認用のテストデータ。後で変更してよい）
  2. データ1行目のE列（例: セル E2）をクリック
  3. 以下の数式を入力して Enter を押す
=[@製作所]&"/"&[@領域]&"/"&[@部門]&"/"&[@工程]
テーブル参照の書き方: [@製作所] はテーブル形式の「同行の製作所列の値」を参照する構文。テーブルにした場合のみ使える。
テーブルではない場合は =A2&"/"&B2&"/"&C2&"/"&D2 と書く（その場合は行コピーが必要）。
自動コピーの確認: 入力後に新しい行を追加すると、E列に同じ数式が自動的に入ることを確認する。確認できれば設定は完了。
パスキーとSharePoint {Path} の対応:
例えばフォルダが「製作所A / 領域1 / 部門2 / 工程3」の場合：
・Excelのパスキー → 製作所A/領域1/部門2/工程3
・SharePointの実際のパス → /sites/サイト名/ライブラリ名/製作所A/領域1/部門2/工程3/ファイル.xlsx
Power Automate の contains() 関数が「パスキーがSharePointパスに含まれるか」で照合するため、部分一致で正しく検出できる。
A4
Excel — データ入力
工程ごとの承認者データを登録する

T_ルーティングテーブルに、フロー対象の工程（フォルダ）と承認者のメールアドレスを1行1件で入力する。
初回は試験対象の工程だけ入力すれば十分。未登録の工程はフローがスキップする。

列入力内容注意点
A: 製作所 SharePoint フォルダ名をそのままコピー＆ペースト 大文字・小文字・全角半角・スペースの有無をフォルダ名と完全一致させる
B: 領域 SharePoint フォルダ名をそのままコピー＆ペースト 同上
C: 部門 SharePoint フォルダ名をそのままコピー＆ペースト 同上
D: 工程 SharePoint フォルダ名をそのままコピー＆ペースト 同上
E: パスキー （数式で自動生成されるため入力不要） 入力した後に自動で更新される。数式が入らない場合はA-3の手順を再確認
F: 宛先メール 承認者の Microsoft 365 メールアドレス 大文字・小文字は問わないが正確に入力する
G: 宛先名 承認者の氏名（任意） フロー内では使用しない。管理用メモとして入力しておく。
フォルダ名の確認方法: SharePoint でそのフォルダを開いた状態で、ブラウザのURLバーを見るか、フォルダをクリックした際に表示されるパンくずリストのフォルダ名をコピーすると確実。

Excel — 完成確認
完成後のテーブルイメージと確認ポイント

以下のような形になっていれば正常。パスキー列（E列）が自動生成されているかを必ず確認する。

A: 製作所 B: 領域 C: 部門 D: 工程 E: パスキー ★自動 F: 宛先メール G: 宛先名
フォルダA 領域1 部門1 工程1 フォルダA/領域1/部門1/工程1 approver-a@example.com 承認者A
フォルダA 領域1 部門1 工程2 フォルダA/領域1/部門1/工程2 approver-b@example.com 承認者B
フォルダA 領域2 部門3 工程5 フォルダA/領域2/部門3/工程5 approver-c@example.com 承認者C

Excel完成チェックリスト

  • テーブル名が「T_ルーティング」になっている（「テーブルデザイン」タブで確認）
  • E列（パスキー）にデータ行すべて数式が入っており、値が表示されている
  • F列（宛先メール）に実際のメールアドレスが入力されている
  • フォルダ名が SharePoint の実際のフォルダ名と一致している（コピー推奨）
  • ファイルが業務ファイルとは別のライブラリに保存されている

B1
Power Automate — フロー作成
自動化クラウドフローを新規作成する
  1. ブラウザで make.powerautomate.com を開き、対象の Microsoft 365 アカウントでサインインする
  2. 左メニューの「＋ 作成」をクリック
  3. 「自動化クラウドフロー」をクリック
  4. 「フロー名」欄に 承認依頼_下書き自動作成 と入力する
  5. 「フローのトリガーを選択してください」の検索欄に SharePoint と入力する
  6. 一覧から「ファイルが作成または変更されたとき（プロパティのみ）」を選択する
  7. 「作成」ボタンをクリックする
「プロパティのみ」を選ぶ理由: ファイルの内容（バイナリ）は必要なく、パスやファイル名などのメタデータだけあれば十分なため。「プロパティのみ」版の方が処理が速い。

B3
デバッグ用アクション（初回確認後に削除可）
【任意】Compose — ファイルの実際のパス値を確認する

パスキーとSharePointパスの照合がうまくいかない場合、ファイルの実際の {Path} 値を確認する必要がある。この Compose アクションで実値を記録しておくと、Excelのパスキーとの差異を特定できる。

  1. トリガーの直後（条件アクションの前）に「＋ 新しいステップ」→「データ操作」→「作成（Compose）」を追加する
  2. 「入力」欄に以下の式を設定する：
アクション名（任意で変更可）
デバッグ_パス確認
入力 式
triggerOutputs()?['{Path}']
  1. フローを保存してテスト実行する（ファイルをアップロードして起動させる）
  2. フローの実行履歴を開き、「デバッグ_パス確認」アクションの出力を確認する
  3. 表示された値（例: /sites/サイト名/ライブラリ名/フォルダA/領域1/部門1/工程1/ファイル.xlsx）とExcelのパスキーを照合する
確認後の処理: パスキーとの一致を確認できたら、この Compose アクションは削除するか、フロー全体を保存し直せばよい。削除しなくても動作には影響しない。

Condition — 条件アクション
条件 — 自分がアップロードしたファイルのみ処理する

「＋ 新しいステップ」→「コントロール」→「条件」を追加する。
重要: 条件式を and() で1行にまとめるとエラーになる。必ずGUIの行単位で設定すること。

左辺の値演算子右辺の値
条件行 左辺欄をクリック →「式」タブを開いて以下を貼り付け → 「OK」をクリック
triggerOutputs()?['body/Editor/Email'] 式
※ ファイルを最後に更新したユーザーのメールアドレスを取得 		次の値と等しい 自分の Microsoft 365 メールアドレスを入力
例: your-email@example.com 固定値
「いいえの場合」ブランチには何も追加しない（空のままでよい）。
他のユーザーがファイルを更新した場合は「いいえの場合」に入りフローがそのまま終了する（下書きは作られない）。
and() 一括式がエラーになる理由: Power Automate の条件アクションは、左辺欄に入力できる式の戻り値が単一の値（文字列・数値・真偽値）でなければならない。and(contains(...), equals(...)) のような複合式を左辺に入力すると「無効な式」エラーが発生する。条件を複数設定したい場合は「＋ 追加」→「行の追加」で1行ずつ追加すること。

「配列のフィルター処理」の式の意味

部分意味
contains(...)第1引数の文字列の中に第2引数の文字列が含まれるかを判定（true/false を返す）

式の各部分の説明

関数/部分役割
body('配列のフィルター処理') フィルター処理アクションの出力配列（一致した行の配列）を取得する
first(...) 配列の最初の要素（一致した最初の行）を取得する。0件の場合は null を返す。
?['宛先メール'] その行の「宛先メール」列の値を取得する（列名はExcelのヘッダーと完全一致）
coalesce(値A, 値B) 値Aが null または空の場合に値Bを返す。0件の場合のフォールバック。Outlook の To フィールドを空にしないためのガード。
アクション名の確認: 式の中の '配列のフィルター処理' は、直前に追加したアクションの表示名と完全一致していなければならない。アクション名が「配列のフィルター処理_1」などになっている場合は式も '配列のフィルター処理_1' に変更する。

PART C — メール本文（HTML 全文）
B-9 の本文欄に「</>」ボタンでHTMLモードに切り替えてから全文貼り付ける

貼り付け前の必須確認

  1. 下書き作成アクションの「本文」欄右上にある 「</>」ボタンをクリックする
  2. 本文欄の表示が「コードビュー」になったことを確認する（枠内に何も文字がない状態）
  3. 以下のHTMLを全文コピーして貼り付ける
  4. 貼り付けた後、通常テキスト表示に戻さずそのまま保存する
本文 HTML （全文をコピーして「</>」モードの本文欄に貼り付け）
<p> 様</p> <p>お世話になっております。</p> <p>下記の案件について、ご確認・承認をお願いいたします。</p> <hr> <p> ■ 案件名　　　：@{triggerOutputs()?['body/{Name}']}<br> ■ 登録日時　　：@{triggerOutputs()?['body/{Modified}']}<br> ■ 承認締切目安：@{formatDateTime(addDays(utcNow(),if(lessOrEquals(dayOfWeek(convertTimeZone(utcNow(),'UTC','Tokyo Standard Time')),2),3,5)),'yyyy年M月d日')} までにご対応をお願いします </p> <hr> <p>荷姿設定書をご確認のうえ、所定のセルにお名前をご記入ください。</p> <p><a href="@{triggerOutputs()?['body/{Link to item}']}">▼ 荷姿設定書を開く</a></p> <p>ご不明な点がございましたら、@{first(split(triggerOutputs()?['body/Editor/DisplayName'],' '))} までご連絡ください。</p> <p>よろしくお願いいたします。</p> <br> <p>--<br> [ここに Outlook の「名前」署名を貼り付ける]</p>

本文内で使用している動的コンテンツの一覧

本文内の参照式取得される内容補足
triggerOutputs()?['body/{Name}'] ファイル名（案件名として使用）
triggerOutputs()?['body/{Modified}'] ファイルの最終更新日時（UTC） 日本時間に変換したい場合は convertTimeZone() でラップする
triggerOutputs()?['body/{Link to item}'] ファイルへのSharePoint URL <a href="...">タグのhrefに使用。HTMLモード必須。

first(split(DisplayName, ' ')) フルネームを空白で分割した最初の要素（苗字） 「山田 太郎」→「山田」
締切日の formatDateTime 式 3〜5営業日後の日付（週末・月曜・火曜考慮）を「yyyy年M月d日」形式で出力 式は下記参照

締切日計算の式（単体で使う場合）

formatDateTime(
    addDays(
        utcNow(),
        if(
            lessOrEquals(
                dayOfWeek(convertTimeZone(utcNow(), 'UTC', 'Tokyo Standard Time')),
                2
            ),
            3,
            5
        )
    ),
    'yyyy年M月d日'
)
曜日（日本時間）dayOfWeek() の戻り値lessOrEquals(..., 2)addDays の値備考
日曜0true+3日→ 水曜
月曜1true+3日→ 木曜
火曜2true+3日→ 金曜
水曜3false+5日→ 月曜
木曜4false+5日→ 火曜
金曜5false+5日→ 水曜
土曜6false+5日→ 木曜
注意: weekday() という関数は Power Automate に存在しない。必ず dayOfWeek() を使うこと。
D
PART D — 動作確認チェックリスト
フロー保存後、以下の順番でテストを実施する

Step 1: フロー保存前の確認

  • トリガーのサイトとライブラリが業務ファイルのライブラリになっている
  • Excel アクションのファイルが 承認ルーティング.xlsx、テーブルが T_ルーティング になっている
  • 配列のフィルター処理の「差出人（From）」に「表内に存在する行を一覧表示」の value が設定されている
  • フィルタークエリが contains(triggerOutputs()?['{Path}'], item()?['パスキー']) になっている
  • 変数の初期化の「値」欄に coalesce(...) 式が設定されており、フォールバックアドレスが自分のアドレスになっている
  • Outlook 下書き作成の「本文」がHTMLモード（</>）で貼り付けられている

Step 2: 正常系テスト

  • 【正常系①】Excelの T_ルーティング に登録済みの工程フォルダに、自分のアカウントでファイルをアップロードする
  • 【正常系②】Power Automate の実行履歴で「成功」になっていることを確認する（通常30秒〜2分以内に実行される）
  • 【正常系③】Outlook の「下書き」フォルダに「【承認依頼】〇〇」という件名の下書きが生成されていることを確認する
  • 【正常系④】下書きの「宛先（To）」が Excel の宛先メール列の値になっていることを確認する
  • 【正常系⑤】「▼ 荷姿設定書を開く」リンクをクリックして SharePoint のファイルが開くことを確認する
  • 【正常系⑥】締切日が週末になっておらず、かつ妥当な営業日になっていることを確認する

Step 3: 除外系テスト

  • 【除外系①】Excelに登録されていない工程フォルダにファイルをアップロードする → 下書きが作られないことを確認
  • 【除外系②】別の人に同じライブラリにファイルをアップロードしてもらう → 自分の下書きが作られないことを確認
  • 【除外系③】承認ルーティング.xlsx を更新する → フローが起動しないことを確認（別ライブラリに置いている場合は正常）

Step 4: Excel のみ変更で宛先が切り替わるか確認

  • Excelの宛先メール列を別のアドレスに変更して保存する
  • 同じフォルダに再度ファイルをアップロードする
  • 新しい宛先で下書きが生成されることを確認する（フローは変更していない）

E
PART E — フォルダ・宛先の追加方法
Power Automate フローは一切触らない。Excel のみ更新する。

基本原則

フロー側のアクションはフォルダや宛先の追加・変更で修正不要な設計になっている。
工程フォルダの追加・承認者の変更はすべて 承認ルーティング.xlsx の T_ルーティングテーブルを編集するだけで反映される。

1
承認ルーティング.xlsx を SharePoint 上で開く

ファイルのあるライブラリ → ファイルをクリックして Excel Online で開く。

2
T_ルーティング テーブルの末尾に1行追加する

テーブルの最後の行の直下のセルに入力を開始するか、最後の行の右端の Tab キーで新しい行を追加する。
製作所 / 領域 / 部門 / 工程 / （パスキー自動）/ 宛先メール / 宛先名 の順で入力する。
パスキー列（E列）はテーブル形式の数式が自動コピーされるため入力不要。

承認者を変更する場合: 既存の行の「宛先メール」列（F列）を直接上書きするだけでよい。次回のファイルアップロード時から新しい承認者宛に下書きが作られる。
3
保存する（以上で完了）

Excel Online は自動保存されるため、特別な保存操作は不要。
次回そのフォルダにファイルがアップロードされた時点から新しい設定が有効になる。Power Automate フローの変更は一切不要。
