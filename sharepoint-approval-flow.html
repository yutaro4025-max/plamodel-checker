SharePoint + Power Automate 承認フロー改善設計 v6

SharePoint列を変更せず、Excelテーブルを制御層として活用する小規模変更設計

SharePoint Excel制御テーブル Power Automate 列変更なし 複数承認者対応（;区切り）
🔒
設計方針: SharePoint列は現状維持・Excelテーブルで裏側制御
  • 既存列（名前 / 承認開始 / 子アイテムの数 / 更新日時 / 更新者 / 確認済）は一切変更しない
  • 承認者情報・締切・リマインド回数・ステータスはExcelテーブルで管理
  • Power AutomateがExcelを読み書きして制御ロジックを実行
  • 承認者は「;」区切りで複数指定可能。誰か1人が承認した時点で完了（ファーストレスポンス方式）
  • 承認行為は荷姿設定書Excel内の特定セルへの記名で実施。フロー③はファイル変更検知＋セル読み取り方式に変更
  • Power Automateの承認コネクタは使用しない（既存Excelへの記名ルールを維持）
  • 試験運用後に本格移行する際もSharePoint側の変更は最小限

SharePoint 現状列（変更なし）

列名種類役割フローでの使い方

現行通知の扱い

「承認開始」チェック時に既存の通知フローが動いている可能性があります。新フロー導入時は既存フローを一時無効化してから新フローを有効化し、二重送信を防いでください。既存フローの宛先が判明次第、Excelテーブルの初期値として転記します。

Excel 制御テーブル設計

ファイル配置

承認管理SharePointサイトの ドキュメント ライブラリ内に 承認管理テーブル.xlsx を配置。
Power AutomateはOneDrive/SharePoint上のExcelを直接読み書きできる（「Excel Online (Business)」コネクタ使用）。

テーブル名: T_承認管理

列名型入力方法説明
SP_案件名 テキスト 手動 or フロー自動 SharePoint「名前」列と一致させる結合キー
SP_アイテムID 数値 フロー自動入力 SharePointアイテムの内部ID（フロー①が記録）
申請者_メール テキスト 手動 or 更新者から自動取得 完了通知・差戻通知の宛先
承認者①_メール テキスト 手動入力 第1承認者のメールアドレス。複数の場合は a@co.jp;b@co.jp のように ; で区切る。誰か1人が承認した時点で完了（ファーストレスポンス）。
承認者②_メール テキスト 手動入力（任意） 第2段承認者。; 区切りで複数指定可。空欄の場合は1段承認として動作。
管理者_メール テキスト 手動入力 エスカレーション先。空欄の場合はCC省略
締切日 日付 フロー自動計算（手動上書き可） 承認開始日 + 3日。Excelの日付形式で保存
ステータス テキスト フロー自動更新 申請中 / 承認者①確認中 / 承認者②確認中 / 承認済 / 差戻 / 期限超過
現在の承認担当 テキスト フロー自動更新 リマインド送信先。複数の場合は ; 区切りのまま保持し、フローが split() で展開して全員に送信。
承認者①_結果 テキスト フロー自動更新 承認 / 差戻 / 未対応
承認者①_対応者 テキスト フロー自動更新 複数指定時に実際に承認/差戻した人のメールアドレスを記録
承認者①_日時 日付時刻 フロー自動更新
承認者②_結果 テキスト フロー自動更新
承認者②_日時 日付時刻 フロー自動更新
リマインド回数 数値 フロー自動更新 初期値: 0。リマインド送信のたびに +1
最終リマインド日時 日付時刻 フロー自動更新 24時間経過チェックに使用
承認セル番地① テキスト 手動入力 荷姿設定書内で承認者①が名前を書くセル番地。例: Sheet1!B5。部署ごとに異なる値を設定。
承認セル番地② テキスト 手動入力（任意） 承認者②用のセル番地。多段承認の場合のみ記入。
備考 テキスト 手動入力（任意） 差戻コメント、特記事項など
■ 結合キー（必須） | ■ 手動入力列 | ■ フロー自動更新列

事前登録の運用フロー

申請者（または管理担当者）がSharePointに案件登録する前に:

1. Excel「T_承認管理」テーブルに1行追加
   → SP_案件名（SharePointの「名前」列と完全一致させる）
   → 承認者①_メール  1人 : user@co.jp
                    複数 : user1@co.jp;user2@co.jp;user3@co.jp  ← ; 区切り
   → 承認者②_メール（任意・多段の場合。複数指定も同様）
   → 管理者_メールを記入

2. SharePointリストに案件を登録

3. 「承認開始」にチェック
   → Power Automate フロー①が起動
   → ExcelからSP_案件名で行を検索
   → ; で分割して承認者全員に同時通知
   → 最初に承認/差戻した1名の結果で後続処理（ファーストレスポンス）
3

Power Automate 構成（フロー単位）

フロー① — 承認開始トリガー・初期通知
トリガー: SharePoint「承認開始」列が True に変更されたとき
[トリガー] SharePoint アイテム変更
    ↓
[条件] 承認開始 = true AND 前の値が false（二重起動防止）
    ↓
[アクション] ExcelテーブルT_承認管理を検索
    - フィルタ: SP_案件名 eq '@{トリガーアイテムの名前}'
    ↓
[条件] 行が見つかったか？
    ├─ NO: 管理者にアラートメール（「Excelに未登録の案件」）→ フロー終了
    └─ YES: 続行
    ↓
[アクション] 変数セット: varApprovers = split(承認者①_メール, ';')
    ※ 例: "a@co.jp;b@co.jp;c@co.jp" → ["a@co.jp","b@co.jp","c@co.jp"]
    ↓
[アクション] Excel行を更新
    - SP_アイテムID = SharePointのアイテムID
    - 締切日        = addDays(utcNow(), 3)
    - ステータス    = '承認者①確認中'
    - 現在の承認担当= 承認者①_メール（; 区切りのまま保持）
    - リマインド回数= 0
    ↓
[アクション] Apply to each: varApprovers の各メールアドレスに対して
    └─ 通知メール送信（宛先: 各アドレス、件名・本文は同一）
       ※ 承認コネクタは使用しない。荷姿設定書Excelへの記名が承認行為。
    ↓
[アクション] 申請者へ受付完了メール送信（更新者のメールを使用）
フロー② — リマインド・期限監視（定期実行）
トリガー: 繰り返し: 毎日 09:00
[トリガー] 繰り返し: 毎日 09:00
    ↓
[アクション] ExcelテーブルT_承認管理を全件取得
    ↓
[アクション] Apply to each（ステータス = '承認者①確認中' or '承認者②確認中' の行のみ）
    ↓
    [条件①] 締切日 < today()
        ├─ YES:
        │   [Excel更新] ステータス = '期限超過'
        │   [メール送信] 現在の承認担当 + 管理者_メールにエスカレーション
        └─ NO:
            [条件②] 最終リマインド日時 から 24時間以上経過している？
                ├─ YES:
                │   [条件③] リマインド回数 >= 5
                │       ├─ YES: 管理者のみに「手動介入要請」メール
                │       └─ NO:
                │           varRemind = split(現在の承認担当, ';')
                │           [Apply to each] varRemind 全員にリマインドメール送信
                │           [Excel更新] リマインド回数+1、最終リマインド日時=now()
                └─ NO: スキップ
フロー③ — 荷姿設定書 変更検知・セル読み取り方式（承認検出）
トリガー: SharePoint「荷姿設定書」フォルダ内のファイルが変更されたとき
[トリガー] ファイル変更検知（荷姿設定書 保管フォルダを監視）
    ↓
[アクション] 変更されたファイル名を取得（拡張子除く）
    ↓
[アクション] T_承認管理を検索
    - フィルタ: SP_案件名 eq '@{ファイル名}'
    ↓
[条件] 行が見つかった かつ ステータスが '承認者①確認中' or '承認者②確認中'
    └─ NO: スキップ（関係ないファイル更新）
    ↓
[アクション] 現在のステータスに応じてセル番地を取得
    - 承認者①確認中 → 承認セル番地①（例: Sheet1!B5）
    - 承認者②確認中 → 承認セル番地②
    ↓
[アクション] Excel Online「Get a cell」
    - ファイル: 変更された荷姿設定書
    - セル: 上記で取得したセル番地
    ↓
[条件] セルに値が入っているか？（承認者名が記入されたか）
    ├─ NO: スキップ（名前未記入 = まだ承認していない）
    └─ YES: 承認確定
        [Excel更新] T_承認管理
            - 承認者①_結果 = '承認'
            - 承認者①_対応者 = セルの値（記入された名前）
            - 承認者①_日時 = now()
        ↓
        [条件] 承認者②_メールが空でないか？ かつ ステータスが承認者①確認中？
            ├─ YES（多段承認あり）:
            │   [Excel更新] ステータス='承認者②確認中'、現在の承認担当=承認者②_メール
            │   varApprovers2 = split(承認者②_メール, ';')
            │   [Apply to each] varApprovers2 全員に通知メール送信
            └─ NO（最終承認）:
                [Excel更新] ステータス='承認済'
                [SharePoint更新] 「確認済」列 = True
                [メール送信] 申請者に承認完了メール（承認者①_対応者 の名前を本文に含む）

運用ルール

申請者ルール

Excelに先に1行登録する
SP_案件名・承認者メールを記入してから「承認開始」をチェック
案件名はSharePointと完全一致
スペース・全角半角のズレで検索が失敗するため注意
取下げはExcelの「ステータス」を「取下げ」に変更
SharePoint側は「承認開始」を OFF に戻す

承認者ルール

メール内のリンクから操作
SharePointを直接開く必要はない
対応期限は通知受信から3営業日
期限超過で管理者にエスカレーション
代理対応は管理者に連絡
管理者がExcelの「現在の承認担当」を変更して対応

管理者ルール

毎朝Excelテーブルを確認
ステータス列でフィルタし「期限超過」「承認者①確認中」を確認
Excelは直接編集可能
承認者変更・締切延長・強制完了はExcel編集で対応
既存フローの二重起動に注意
新フロー導入前に既存の「承認開始」トリガーフローを確認・無効化
通知先が変わる場合はExcelを更新
SharePoint列の変更は不要。Excel1行の修正のみで完結

Excel制御テーブル固有の確認

テストケース確認内容
承認者①に ; 区切りで3名登録3名全員に通知メールが届くか
3名のうち1名が承認残り2名の保留承認がキャンセルされ完了処理が走るか
3名のうち1名が差戻残り2名の保留承認がキャンセルされ申請者に差戻メールが届くか
リマインド送信時に ; 区切り3名が登録済み3名全員にリマインドが届くか
Excelの「承認者①_メール」を試験運用中に変更次のリマインドから新しいアドレスに送信されるか
荷姿設定書の承認セルに名前を記入フロー③が検知し、T_承認管理とSharePoint「確認済」が更新されるか
承認セル番地が間違っている（空セルを参照）セルが空のためスキップされ、誤って承認完了にならないか
関係ないExcelファイルを荷姿設定書フォルダで編集T_承認管理に合致しない案件名のためスキップされるか
承認者②_メールが空の状態で承認者①が承認1段承認として完了処理が走るか
同一案件名が複数行登録された場合フローが正しく1行を特定できるか（重複チェック要）

締切日の式（Power Automate「式」タブに貼り付ける）

formatDateTime(
    addDays(
        utcNow(),
        if(
            lessOrEquals(
                dayOfWeek(convertTimeZone(utcNow(), 'UTC', 'Tokyo Standard Time')),
                2
            ),
            3,
            5
        )
    ),
    'yyyy年M月d日'
)

日本時間基準で曜日を判定 → 土日をまたぐ場合は+5日・それ以外は+3日 → 「2025年6月5日」形式で出力

動作確認チェックリスト

#確認内容期待結果
1自分がチェック → Outlook下書きが作成されるか件名・本文・締切日が正しく入っている
2他人がチェック → 下書きが作成されないかスキップされて何も起きない
3水〜土にチェック → 締切日が+5日の平日になるか週末に当たらない
4日〜火にチェック → 締切日が+3日の平日になるか週末に当たらない

注意：重複起動の防止

SharePointのアイテムが更新されるたびにトリガーが発火します。
「承認開始」を一度チェックした後に別の列を編集すると、条件①（承認開始=true）が再び通ってしまい下書きが複数作られます。
対策として条件に 「更新前の承認開始の値 = false」 を追加してください。
Power Automateのトリガー設定で「列が変更されたとき」に限定するか、条件式に @{triggerOutputs()?['body/承認開始_Previous']} を使います。
