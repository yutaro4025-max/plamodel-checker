対象フォルダ内 かつ 自分の操作か
条件アクションは GUI の2行 AND 接続で設定する（式タブの and() 一括式はエラーになる場合がある）

行左辺（式タブ）演算子右辺
1行目 triggerOutputs()?['{Path}'] 次の値を含む ①フォルダA
AND 「＋追加」→「行の追加」→ 接続子を AND に設定

宛先ルーティングテーブル設計（承認ルーティング.xlsx）

設計方針

フォルダが増えてもフローを触らずExcelに1行追加するだけで対応できる。
Switch アクションは件数が増えると管理が困難になるため採用しない。

テーブル名: T_ルーティング（承認ルーティング.xlsx に作成）

フォルダキーワード宛先メール宛先名（表示用）
①フォルダAapprover-a@example.com承認者A
②フォルダBapprover-b@example.com承認者B
③フォルダCapprover-c@example.com承認者C
（追加するだけ）

ファイルはSharePointの任意のドキュメントライブラリに配置。Power Automateの「Excel Online (Business)」コネクタから参照する。

フロー内での参照式

// ① 行一覧取得後、Filter array で Path と部分一致する行を絞り込む
contains(triggerOutputs()?['{Path}'], item()?['フォルダキーワード'])

// ② 絞り込んだ結果の先頭行から宛先メールを取得（varTo にセット）
first(body('配列のフィルター処理'))?['宛先メール']

// ③ フォールバック（一致なし時は自分に送る）
coalesce(first(body('配列のフィルター処理'))?['宛先メール'], 'your-email@example.com')

メール本文（HTML形式 — コード表示に切り替えて貼り付け）

重要: 本文はHTML形式で記述する

プレーンテキストのままではURLが表示されるだけでクリックできない。
Power Automateの本文欄で 「コード表示（</>）」に切り替えてから 以下のHTMLを貼り付けること。

本文 HTML （コード表示に切り替えてから貼り付け）
<p> 様</p> <p>お世話になっております。</p> <p>下記の案件について、ご確認・承認をお願いいたします。</p> <hr> <p> ■ 案件名　　　：@{triggerOutputs()?['body/{Name}']}<br> ■ 登録日時　　：@{triggerOutputs()?['body/{Modified}']}<br> ■ 承認締切目安：@{formatDateTime(addDays(utcNow(),if(lessOrEquals(dayOfWeek(convertTimeZone(utcNow(),'UTC','Tokyo Standard Time')),2),3,5)),'yyyy年M月d日')} までにご対応をお願いします </p> <hr> <p>荷姿設定書をご確認のうえ、所定のセルにお名前をご記入ください。</p> <p><a href="@{triggerOutputs()?['body/{Link to item}']}">▼ 荷姿設定書を開く</a></p> <p>ご不明な点がございましたら、@{first(split(triggerOutputs()?['body/Editor/DisplayName'],' '))} までご連絡ください。</p> <p>よろしくお願いいたします。</p> <br> <p>-- <br> [ここにOutlook「名前」署名の内容を貼り付け]</p>

本文内の変数取得される値

締切日の式

Power Automate「式」タブ / または HTML本文に直接埋め込む

formatDateTime(
    addDays(
        utcNow(),
        if(
            lessOrEquals(
                dayOfWeek(convertTimeZone(utcNow(), 'UTC', 'Tokyo Standard Time')),
                2
            ),
            3,
            5
        )
    ),
    'yyyy年M月d日'
)

日本時間で曜日判定 → 日・月・火は +3日 / 水・木・金・土は +5日（全曜日で週末を回避して3営業日後に着地）

実装時のつまずきと対処（記録）

①
フォルダ条件が成立しない（{Path} の実値と指定文字列が不一致）
原因
{Path} の実際の値と条件で指定した文字列がずれていた（スラッシュ位置・内部パス差異）。Composeアクションで実際の値を確認するまで見えない。
対処
フォルダ名の部分一致（contains）に変更。フルパスの一致を求めない。
実値確認は Compose に triggerOutputs()?['{Path}'] を入れてテスト実行で確認。
②
「ユーザー条件だけでよいのでは？」という設計判断
懸念
自分の更新で分岐しているのだからフォルダ条件は不要では？と考えた。
結論
ライブラリ全体を監視しているため業務外ファイルにも反応するリスクがある。フォルダ条件は必須。 フォルダ ＋ ユーザーの2軸で制御する。
③
{Path} に値を入力する必要があるのか不明
誤解
{Path} は何か入力が必要なフィールドと思っていた。
正解
{Path} はトリガーが自動的に取得する値。条件式の中で参照するだけでよく、入力は不要。
④
条件式（equals / contains）をどちらの辺に入れるか迷う
原因
GUI形式（左辺・右辺）と Expression形式（式として直接書く）の違いで迷う。
対処
条件全体を「式」タブで and(contains(...), equals(...)) と一括で書く。GUI形式は使わない。
⑤
メール宛先が必須で保存できない
原因
Outlook「下書き作成」コネクタの To フィールドは必須。空欄のままではフロー保存不可。
対処
To に自分のメールアドレスを仮設定。下書きを開いて送信前に宛先を変更する運用で対応。
⑥
「Link to item」を埋めてもURLがクリックできない（最大のはまりどころ）
原因
本文がプレーンテキスト扱いになっているためURLが文字列として表示されるだけ。HTMLリンクとして認識されない。
解決策
本文欄を 「コード表示（</>）」に切り替えてHTML形式で記述。
リンクは <a> タグで生成する。

<a href="@{triggerOutputs()?['body/{Link to item}']}">荷姿設定書を開く</a>

動作確認チェックリスト

  • 対象フォルダにファイルをアップロード → Outlook下書きフォルダに「【承認依頼】〇〇」が作成される
  • 別フォルダにファイルをアップロード → 下書きが作成されない（フォルダ条件で除外）
  • 他の人がファイルを更新 → 下書きが作成されない（ユーザー条件で除外）
  • 「▼ 荷姿設定書を開く」リンクがクリックできる（プレーンテキストになっていないか）
  • 締切日が週末に当たっていないか（水〜土曜に実行して確認）
  • 苗字のみが表示されている（フルネームになっていないか）
  • 署名が本文末尾に入っているか
6

この実装で得られた知見

  • {Path} は「見た目の値」と「実際の値」がずれる — Compose で実値を確認してから条件を書く
  • 条件は「業務範囲（フォルダ）」と「実行者（ユーザー）」の2軸で管理する — どちらか一方では抜け漏れが生じる
  • 複数条件は GUI の2行 AND 接続が安定 — and() 一括式は動作環境によってエラーになる。各行を左辺／演算子／右辺で分けるほうが確実
  • Power Automateはデータ取得と表示が別 — 値が取れていても表示方法が間違うと機能しない
  • メール本文のリンクはHTML化が必須 — プレーンテキストのままではクリック不可。コード表示に切り替えて <a> タグを使う
  • To フィールドは必須 — 下書き作成でも空欄不可。Excelルーティングテーブルから宛先を動的に取得し、フォールバックで空を防ぐ
